# 03 명세 — 기술 구성

2026-11-20 사용자 확정 3가지 + 그에 따라 정한 세부 구성. "제안" 표시는 아직 승인 전이다.

## 1. 확정 (2026-11-20)
| 항목 | 결정 |
|---|---|
| 실시간 방식 | **자체 게임 서버** (Node.js 프로그램 하나). 서버가 심판·채점을 맡는다 |
| 방 만들기 권한 | **선생님 비밀번호**. 서버의 `.env` 파일에만 저장, 선생님이 직접 적는다 |
| 문제 세트 저장 | **선생님 브라우저** (그 PC에 남음). 다른 PC에서는 엑셀을 다시 올린다 |

## 2. 전체 그림
```
[선생님 브라우저] ─┐
[학생 브라우저] ───┼── 웹소켓(실시간 연결) ── [게임 서버 1개] ── 방 여러 개 (메모리에 보관)
[학생 브라우저] ───┘                              └ 같은 서버가 게임 화면 파일도 내려 준다
```
- 서버 프로그램 하나가 **화면 파일 제공 + 실시간 통신**을 모두 한다. 따로 DB는 두지 않는다.
- 방·게임 상태는 서버 메모리에만 있고, 게임이 끝나면(또는 서버를 끄면) 사라진다. 학습 기록은 게임 종료 때 선생님 화면에서 CSV로 내려받는다.

## 3. 서버가 맡는 일 (참고작의 약점 해결)
- **방 만들기**: 비밀번호가 맞을 때만 4자리 방 번호 발급. 비밀번호는 브라우저 소스에 들어가지 않는다. 여러 번 틀리면 잠시 막는다.
- **채점**: 정답은 서버에만 있다. 학생에게는 문제와 (섞은) 보기만 보내고, 학생이 낸 답을 서버가 맞는지 판정한다.
- **심판**: 역할 배정, 잡기·얼리기 거리 확인, 쿨타임, 장치 사용(쿨타임·보호 시간), 복구율, 회의·투표, 승패.
- **이동**: 학생 화면이 자기 위치를 초당 여러 번 보내고, 서버는 "너무 빠르게 움직였는지"만 확인해 다른 사람에게 전달한다. (제안: 초당 10회)
- **재접속**: 연결이 끊겨도 60초 안에 돌아오면 이어서 한다 (참고작과 같음). 같은 이름으로 다시 들어와도 이어진다.
- **도중 입장 (2026-11-20 확정)**: 게임이 시작된 방에도 들어올 수 있다. 시작 자리 둘레에 나타난다.
- **역할 인원 추천 (2026-11-20 확정)**: 술래·방해꾼 수는 인원에 맞춰 추천하고(기본 "자동"), 선생님이 1~3명으로 바꿀 수 있다. 기준은 `shared/config.js` 의 `recommendChasers`.
  - 역할 배정 자체는 4단계(얼음땡)에서 만든다. 도중에 들어온 학생은 **학생 역할**로 시작한다 (2026-11-20 확정). 인원이 늘어 추천 술래 수가 올라가면 선생님 화면에 "술래를 1명 더 늘릴까요?" 추천을 띄운다 (제안).

## 4. 화면(브라우저) 쪽
- 프레임워크 없이 기본 웹 기술(HTML + Canvas + JavaScript)로 만든다. 빌드 과정이 없어 고치기 쉽다. (제안)
- 맵은 `maps/*.json` 을 읽어 코드 도형으로 그린다 (`01-spec.md`).
- 엑셀 읽기: 선생님 브라우저에서 바로 읽고, 확정한 문제 세트만 방을 만들 때 서버로 보낸다. 엑셀 파일 자체는 서버에 올라가지 않는다.
- 태블릿: 화면 조이스틱 + 버튼. PC: 방향키/WASD.

## 5. 폴더 구조 (제안)
```
outputs/code/
  server/        게임 서버 (방, 심판, 채점)
  client/        화면 (학생·선생님 공용, 주소로 구분)
  maps/          맵 데이터
  shared/        서버와 화면이 같이 쓰는 규칙 값 (거리, 쿨타임 등)
  .env.example   비밀번호 등 설정 예시 (.env 는 git 제외)
```

## 6. 필요한 것
- Node.js: 이 PC에 설치되어 있음 (v24.16.0 확인).
- 외부 라이브러리: 웹소켓용 `ws` 1개 (제안). 설치는 외부 다운로드이므로 **설치 전에 사용자에게 묻는다**.
- 엑셀 읽기: 양식이 단순해서 직접 만든 작은 읽기 코드로 시작하고, 문제가 생기면 라이브러리(SheetJS)를 검토한다. (제안)

## 7. 개발 중 실행
- 이 PC에서 서버를 켜고 브라우저 탭 여러 개(선생님 1 + 학생 4 이상)로 시험한다.
- 같은 와이파이의 태블릿은 `http://이PC주소:포트` 로 접속해 시험할 수 있다 (윈도우 방화벽 허용 필요 — 확인 필요).

## 8. 확인 필요 (수업에 쓰기 전까지 정하면 됨)
1. **서버를 어디에 켜 둘 것인가**: 선생님이 이미 쓰는 서버 / 클라우드 서비스 / 교실 PC. 인터넷 주소(https)가 필요하고, 학교 와이파이에서 접속이 되는지 실제로 확인해야 한다.
2. 게임 이름.
3. 한 서버에서 동시에 열 수 있는 방 수 제한 (제안: 20개).

## 9. 만드는 순서 (제안)
1. 뼈대: 서버 + 방 만들기/입장 + 대기방
2. 맵 그리기 + 이동 + 충돌 + 다른 사람 보이기 (몬스터 체육관)
3. 엑셀 올리기 + 미리보기 + 단말기에서 문제 풀기 + 복구율
4. 얼음땡 모드 (잡기·땡·승패) + 미끄럼틀·개구멍
5. 선생님 화면 (전체 지도, 학습 기록, CSV)
6. 어몽어스 모드 (방해꾼, 회의·투표)
7. 수업용 서버에 올리기
